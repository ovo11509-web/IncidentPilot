**功能分支**：`feature/incident-platform`（沿用当前工作区，不新建分支）
**创建日期**：2026-10-05
**状态**：2026-10-05 用户明确“执行”确认当前方案，本地验收完成，18/18任务
**输入**：用户要求继续 OBS 作者审阅，并推进 LAB-001：复用本地隔离测试，形成故障回放与证据报告的最小方案。

## 用户场景与测试（必填）

### 用户故事 1 - 选择并重放既有故障（优先级：P1）

开发者从可读目录选择一个故障，用一个入口重新运行，得到该次独立实验的结果，而无需拼接多模块测试命令。

**优先级理由**：已有故障检查，缺少稳定的操作入口。
**独立测试**：列出目录，运行告警重试恢复场景；验证真实本地业务断言、结果与本轮证据相符。
**验收场景**：

1. **Given** 本地前置条件齐全，**When** 运行一个合法场景，**Then** 只运行该场景声明的检查，生成唯一运行目录和真实结果。
2. **Given** 未知场景、不可用的本地依赖或非隔离配置，**When** 请求运行，**Then** 明确拒绝或报告环境受阻，不连接开发数据库或远程服务。
3. **Given** 曾有成功运行，**When** 同场景再次失败，**Then** 两次记录分别保留，不复用旧报告判定通过。

### 用户故事 2 - 解释故障与恢复证据（优先级：P1）

开发者从报告了解注入点、预期、实际数据库事实、稳定业务身份、可用 Trace 和验证边界。

**优先级理由**：实验必须帮助解释失败，而非仅展示测试绿灯。
**独立测试**：运行 Worker 崩溃与回执通道场景；逐一核对同一执行的恢复、单次应用和 UNKNOWN 收敛证据。
**验收场景**：

1. **Given** Worker 真正崩溃后恢复，**When** 查看报告，**Then** 能区分进程尝试和逻辑执行，并用稳定身份与实际应用次数说明结果；Trace 可以跨重启变化。
2. **Given** 回执通道故障，**When** 查看报告，**Then** 分列三个子场景，说明不重复调度、未知状态及可信迟到回执的事实。
3. **Given** 固定发布器、SQL 故障注入或直接服务调用，**When** 查看报告，**Then** 明示证据层级，不能标为实际 Broker 或完整 HTTP 主链验收。

### 用户故事 3 - 独立核验与再次复现（优先级：P2）

审阅者能够只读验证本地归档完整性，并在另一轮隔离实验中复现相同场景契约。

**优先级理由**：未提交工作区和历史制品不能只靠 HEAD 标识。
**独立测试**：验证正常归档，再复制并修改一个制品、删除必需证据、混入旧报告，均应拒绝通过；重复实验使用新目录。
**验收场景**：

1. **Given** 真实完整的通过归档，**When** 只读验证，**Then** 检查结果、制品完整性和来源一致性，不启动服务或执行处置。
2. **Given** 文件被修改、来源缺失、必要检查跳过或失败，**When** 验证，**Then** 返回失败并指出安全的定位信息，不补造证据。

### 边界情况

- Docker 不可用、子进程超时或用户中断：保留已生成失败制品；没有完成证明则不得通过，不能杀死其他运行的资源。
- 同时运行两个实验：首版入口使用仓库内专用运行锁，第二次拒绝；不清理历史报告或运行目录。
- 崩溃导致 Span 未导出：缺失不证明未执行；以业务事实判断，在承诺 Trace 的完成路径缺失必要证据时实验不通过。
- 同一测试产生多个子场景：一个实验可包含多个独立 Execution，不把总应用次数误判为单执行重复。

## 需求（必填）

### 功能需求

- **FR-001**：MUST 提供版本化目录，首版六类场景为告警重试/人工重放、Outbox 投递恢复、Worker 崩溃恢复、回执通道故障、黄金主链、诊断安全拒绝；每项声明注入点、执行范围、预期和证据层级。
- **FR-002**：MUST 提供列出目录、运行单场景、运行全部、只读验证归档四种操作；不支持任意命令或任意连接目标。
- **FR-003**：每次运行 MUST 生成唯一运行身份并隔离本轮输出；仅采纳与本轮、场景和测试选择一致的报告及证明，不能只凭修改时间认定来源。
- **FR-004**：MUST 复用已有安全模拟审批及幂等协议；只有实验拥有的临时本地资源可被注入故障，不扩大真实工具或数据权限。
- **FR-005**：MUST 保留通过、业务断言失败、环境受阻及可捕获中断的真实结果；外层被强制杀死时保留未完成状态，由验证拒绝通过。失败不得被后续成功覆盖。
- **FR-006**：MUST 输出安全可读报告，含输入版本、故障位置、预期/实际、执行身份、数据库断言/投影、可用 Trace、原始证明引用和未验证事项。
- **FR-007**：MUST 以持久业务事实说明幂等和恢复；已有 Trace 场景核对实际父子关系及跨恢复稳定身份，不以 Span 数量或缺失替代执行结论。
- **FR-008**：MUST 显式区分完整双 JVM、真实 PostgreSQL、直接调用、SQL fixture 与发布器替身；不会声称真实 Broker、跨主机、生产或性能验收。
- **FR-009**：MUST 保存命令参数、退出码、选定测试及数量、实际环境、分支/HEAD、相关源码内容摘要和制品完整性摘要；秘密和内容不得出现在新增报告中。
- **FR-010**：MUST 只读核验归档来源、必需证明、结果和完整性；任何失败、错误、跳过、旧报告、缺失、篡改或未完成状态都不能返回通过。
- **FR-011**：MUST 提供自动检查覆盖入口选择、路径边界、来源错配、失败/跳过/缺失证据、篡改及重新运行隔离；六类场景均需实际本地复跑作为交付门槛。
- **FR-012**：首版 MUST 保持业务协议、Schema、生产配置、页面及默认 Java 门禁行为；不增加外部服务依赖，完整实验由用户显式运行。

### 关键实体（功能涉及数据时填写）

- **场景定义**：稳定 ID、版本、故障位置、检查选择、事实预期、证据范围。
- **实验运行**：唯一身份、所选场景、开始/结束、来源版本、真实执行结果。
- **场景结果**：关联检查、子场景、预期/实际、安全业务身份、证明与限制。
- **证据归档**：本轮报告、事实、Trace、安全日志及完整性清单；不是新的业务事实源。

## 成功标准（必填）

### 可度量结果

- **SC-001**：六类目录全部可列出并单独运行，未知场景拒绝；单次运行不包含其他未选场景。
- **SC-002**：六类场景均真实本地通过；每类报告和必需证明全部可核对，失败、错误、跳过均为零，不使用历史结果补齐。
- **SC-003**：恢复及回执场景中的每个逻辑执行应用次数不超过一；报告能展示稳定身份、实际恢复/收敛及其证据。
- **SC-004**：旧报告、缺失、错配、篡改、失败、跳过及未完成七类负例全部拒绝通过；两次复跑归档互不覆盖。
- **SC-005**：新报告仅含允许的安全字段；既有逐实际秘密扫描仍通过，新增制品加入扫描范围，所有声称完成的证明均包含可用来源与摘要。

- 首版采用本地命令入口与证据报告；用户在当前spec/plan/tasks呈现后明确“执行”，确认本方案及本地隔离实施边界。
