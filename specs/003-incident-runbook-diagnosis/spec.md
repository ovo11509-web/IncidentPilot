# 功能规格：Incident Runbook RAG 诊断与可复核引用

**功能分支**：`feature/incident-platform`（保持当前分支，功能目录独立）

**创建日期**：2026-10-03

**状态**：v1.0 已确认，2026-10-03 用户“确认执行”；授权本地实施与隔离验证，不授权提交、推送、部署、付费调用或真实处置。

**输入**：补齐“告警→诊断→人工审批→安全模拟处置”；先明确样例、元数据、快照、引用、证据和离线评测，生成待确认的 spec/plan/tasks；保留现有修改，不调用付费模型或真实基础设施，不提交、推送或部署。

## 用户场景与测试（必填）

### 用户故事 1 - 检索适用且可复核的 Runbook（优先级：P1）

值班人员按 Incident 的服务、环境、资源和症状查找有效 Runbook，查看本次实际返回的原文、版本和位置；知识更新后仍能复核历史引用。

**优先级理由**：稳定来源和适用性是诊断的前提。

**独立测试**：无需模型/MCP，使用版本化语料运行真实本地检索，验证范围过滤、排序和历史引用回放。

**验收场景**：

1. **Given** 两条同指纹告警形成一个 Incident，**When** 检索，**Then** 仅返回已发布、未过期且服务/环境/资源适用的 Runbook，并附稳定引用。
2. **Given** 发布新版本或撤回旧版本，**When** 回放旧诊断，**Then** 仍可核对原版本摘录及摘要；新检索不选撤回版本。
3. **Given** 无语料、无匹配或检索失败，**When** 诊断，**Then** 明确无依据或失败，不能用其他环境的资料补足证据。

### 用户故事 2 - 理解有证据的诊断和不确定项（优先级：P1）

人员能区分“告警源报告的症状”“Runbook 条款”“候选解释”和“缺少的观测”；每条建议可追溯快照事实与实际检索证据。

**优先级理由**：来源告警不是已证实根因，有引用也不代表任意建议正确。

**独立测试**：固定快照与检索结果，注入合规、伪造、无依据、矛盾及提示注入输出，核对公开结果与持久记录。

**验收场景**：

1. **Given** 证据适用并满足审阅规则，**When** 诊断完成，**Then** 返回候选解释、事实 ID、引用 ID、前提、只读检查及不确定项，不能称根因已经确认。
2. **Given** 输出引用本次未返回证据、未知事实或篡改原文，**When** 校验，**Then** 记录 `INVALID_EVIDENCE`，无可转换的处置建议。
3. **Given** 只有 OOM 标题，无 GC/堆/日志观测，**When** 诊断，**Then** 只能说明来源报告 OOM，列出只读检查，不能断言内存泄漏或建议真实重启。
4. **Given** 捕获后新增关联告警或主状态改变，**When** 发布或选择建议，**Then** 显示过时并阻止新 Action 转换，保留原诊断。

### 用户故事 3 - 将建议交给服务端人工审批（优先级：P2）

人员显式选择有效的模拟建议，系统创建关联诊断的待审批 Action；批准、票据、派发和 UNKNOWN 仍由 Spec B 裁决。

**优先级理由**：补齐黄金路径而不扩大自动化授权。

**独立测试**：预置诊断验证转换、重复、冲突、过时与越权；接既有隔离模拟链验证拒绝零应用、批准一次应用。

**验收场景**：

1. **Given** 有效诊断与登记目标，**When** 有权限人员选择建议，**Then** 原子创建 `PENDING_APPROVAL` Action、诊断关联与 Timeline，不批准、不调用工具。
2. **Given** 同一来源请求已接受，**When** 重试相同绑定，**Then** 返回同一 Action；诊断、建议或绑定不同则冲突。
3. **Given** 首次 Action 被拒绝，**When** 人员以新请求提出新 Action 并批准，**Then** 首次无执行，第二次最多一次模拟应用，证据和审批可复核。
4. **Given** 已关闭、无有效建议、真实目标或无权限，**When** 转换，**Then** 失败关闭，无 Action 或副作用。

### 用户故事 4 - 离线评测与黄金路径复现（优先级：P2）

评审者用版本化数据集分别验证真实本地检索、固定输出编排、安全降级与 A+B+C 黄金路径；固定替身不得被表述成真实模型质量。

**优先级理由**：有实际可复现证据后才能宣布完成。

**独立测试**：重复运行固定语料和配置；故意降低命中、伪造引用或遗漏用例，确认门禁失败。

**验收场景**：

1. **Given** 完整离线集，**When** 实际检索，**Then** 保存逐例预期和真实排序，报告命中、适用性及所有分母。
2. **Given** 固定模型响应测试，**When** 运行校验，**Then** 只证明编排与安全，不把固定返回值当检索/模型质量。
3. **Given** 两告警→一个 Incident→带证据诊断→拒绝→新 Action 批准→模拟一次应用，**When** 主应用重启，**Then** 快照、引用、诊断、关联、审批、回执与只追加 Timeline 完整。

### 边界情况

- 未关联告警、超长告警集截断、事实矛盾、缺少前提、未知 ID、摘要不符、同分检索、空语料。
- 相同 Runbook/version 被不同内容覆盖，撤回或过期版本，跨服务/环境相似症状。
- 告警或文档中出现“忽略审批/执行命令”：只能作为不可信数据，不能成为工具指令。
- 检索/生成失败、超时、进程中断、完成响应丢失、同请求并发与冲突完成。
- 选择建议与新告警、主状态变更、关闭或语料撤回竞争；重新校验后失败关闭。
- 追加诊断 Timeline 不能把自身诊断误判为新事实；保守主版本变化与事实摘要分别记录。

## 需求（必填）

### 功能需求

- **FR-001**：首版 MUST 提供五类中文模拟 Runbook：资源过载、Java OOM、连接池耗尽、健康检查失败、消息积压；显式注明 IncidentPilot 自建、非生产操作手册。
- **FR-002**：Runbook MUST 有稳定 ID、不可变版本、标题、归属/作者、来源、服务/环境/资源范围、症状词、审阅日期、有效期、发布状态、全文摘要和章节 ID；新版本不得覆盖历史内容。
- **FR-003**：检索 MUST 在排序前限制有效适用版本，并在返回引用与新 Action 转换时再次校验；历史回放不得替换成当前版本。
- **FR-004**：快照 MUST 由 Incident 权威服务一致读取并冻结主版本/状态、Timeline 水位、已关联 Alert 身份及白名单症状、来源/接收时间、范围、截断信息和摘要；客户端自报或未关联 Alert 不得成为权威事实。
- **FR-005**：事实 MUST 有稳定 ID 与来源位置；告警描述仅为来源报告，无指标/日志时 MUST 明确缺失，不得冒充实时基础设施验证。
- **FR-006**：诊断 MUST 保存请求身份、快照、查询/范围/实际排序、语料版本、取回证据、生成器/规则/Prompt 版本、候选解释、建议、不确定项和安全失败码。
- **FR-007**：引用 MUST 指向本次实际返回证据，含 Runbook ID/version、章节、位置、原文、全文/片段摘要；源文件改变或删除后仍能复核。摘要证明完整性，不证明语义正确。
- **FR-008**：每条解释与建议 MUST 同时关联事实和引用，声明前提、缺失与风险；矛盾、无支持或不适用时降级，不得整批“一条有效全部放行”。
- **FR-009**：校验 MUST 拒绝未知 ID、伪造摘录、篡改摘要和不满足前提；首版限定审阅规则与抽取条款，不能以引用存在性声称已证明自由文本蕴含。
- **FR-010**：不足证据返回 `INSUFFICIENT_EVIDENCE`，运行失败 `FAILED`，非法输出 `INVALID_EVIDENCE`；均无可转换建议。过时是派生属性，历史结果不覆盖。
- **FR-011**：诊断 MUST 只提出建议，不批准 Action、不签票据、不调用 MCP 写工具、不改变 Incident 主状态，不把模拟成功当根因正确的证明。
- **FR-012**：人员选择 MUST 使用服务端登录/权限、最新 Incident 版本、诊断摘要和来源请求 ID；核对建议、事实、语料状态与服务端模拟目标映射；仅创建 Spec B `PENDING_APPROVAL`。
- **FR-013**：转换幂等和来源关联 MUST 有数据库约束；Action、来源 link 和 Timeline 同一 Incident 本地事务原子写入；无跨领域外键/JOIN/写事务，不改 B `action-binding-v1` 字节语义。
- **FR-014**：结果和证据 MUST 只追加，终态结果恰好一个稳定键 Timeline 事实；中断可查询并收敛安全失败，默认不自动重跑生成器。
- **FR-015**：人员接口 MUST 沿用当前 `admin` 服务端门禁；大小、截止、事实/引用数量有界；提示注入不能控制工具，敏感载荷及思维链不进日志/Timeline。
- **FR-016**：默认运行/验收 MUST 无付费模型、远程 Embedding/Rerank、对象存储或真实基础设施调用；真实检索与固定响应校验分开报告，无外部回退。
- **FR-017**：离线集 MUST 版本化、人工审阅，覆盖正例、无依据、作用域干扰、过期/撤回、冲突、伪造与注入；gold 标签不能作为检索输入。
- **FR-018**：评测 MUST 输出逐例、所有分母、版本/摘要、配置、实际命令、失败/跳过原因；缺例、零分母或失败阻止宣称通过。
- **FR-019**：MUST 验证确定性契约、真实 PostgreSQL 约束/事务/并发/权限、隔离黄金路径与重启；构建绿色不等于真实模型或生产验收通过。

### 关键实体（功能涉及数据时填写）

- **RunbookVersion / CorpusManifest**：不可变内容与发布范围，检索领域拥有。
- **IncidentSnapshot / SnapshotFact**：权威输入、来源事实和截断标记。
- **DiagnosisRequest / DiagnosisResult**：幂等请求、运行状态及只追加终态证据。
- **RetrievalEvidence / Citation**：真实检索结果与可核对位置。
- **Recommendation / DiagnosisActionLink**：有前提的建议和待审批 Action 来源。
- **EvaluationCase / EvaluationRun**：版本化预期与实际结果，不是生产诊断事实。

## 成功标准（必填）

### 可度量结果

- **SC-001**：五类 Runbook 的公开引用以原文、位置、摘要复核成功率为 100%，发布新版本后不变。
- **SC-002**：正例 Top-3 Runbook 命中率 ≥90%，作用域/失效版本泄漏为 0；报告总体与逐类分母。自动实测结果见 `docs/changelog.md`；FR-017/T028人工标签复核于2026-10-04完成，签署及剩余覆盖见review/v2。
- **SC-003**：引用可解析及原文/摘要一致率均为 100%；伪造事实/引用、无依据可执行建议接受数为 0。
- **SC-004**：无证据、矛盾、非法输出、注入和过时例的降级/拒绝命中率为 100%。
- **SC-005**：拒绝产生 0 次模拟应用，批准的新 Action 至多 1 次应用；重复转换/重放不新增副作用；诊断直接写调用为 0。
- **SC-006**：黄金路径重启后全部快照/证据/关联/审批/回执可查，Timeline 无重复且普通应用角色不能修改/删除历史事实。
- **SC-007**：同语料/数据集/算法/配置重复运行，排序、证据及门禁判定相同（时间/运行 ID 可不同）；执行覆盖率 100%，明确固定生成器与未运行的真实模型评测。

## 假设

- 推荐五类模拟语料、至少 30 例（每类两正例、一不足、一作用域、一失效、一注入）；另加矛盾/伪造契约例。
- 推荐首版确定性本地关键词检索与抽取式结构化诊断；固定模型输出仅用于校验测试，不建设真实模型 adapter。
- 唯一写操作为既有 `simulation.set-state` v1、`SIM_SERVICE`、`desiredState=READY|PAUSED`；模拟状态不是真实故障修复证明。
- 无 Incident UI、通用 IAM/工作流、自动告警触发诊断、诊断 Outbox 消费者、生产模型或向量召回对比。
- Spec A/B 当前代码、Schema 与执行记录优先于旧“尚未实现”文档；历史冲突见 research，未改写历史决策。
