## 用户场景与测试（必填）

### 用户故事 1 - 从请求与业务标识查清事件过程（优先级：P1）

响应人员拿到一次请求的响应标识，能在安全日志中找到同次请求；告警持久化后，可以从告警身份定位其后续 Incident，再以 Incident 身份串联诊断、建议选择、审批、执行和回执。不同层级标识含义明确，不会把多个告警错误合并为同一个告警身份。

**优先级理由**：业务事实已有稳定身份，首先让排错者能沿这些身份查到实际操作。

**独立测试**：追踪关闭时，在隔离环境提交两个同 episode 告警及重复告警，完成诊断与拒绝审批；核对请求响应、日志和持久化身份，不依赖追踪后端。

**验收场景**：

1. **Given** 首次告警，**When** 接收后重复提交相同告警，**Then** 两次响应具有不同请求尝试标识，而告警及其首次接收关联标识相同，无新增业务事实。
2. **Given** 两个不同告警聚合为同一 Incident，**When** 查询或诊断该事件，**Then** 能区分两个告警的关联标识，聚合后的操作共同携带同一 Incident 身份；未关联的告警不伪造 Incident 身份。
3. **Given** 成功、鉴权拒绝、非法输入或冲突请求，**When** 获得响应，**Then** 响应与该次安全日志使用相同请求尝试标识，既有响应成功码和业务结果保持。
4. **Given** 历史 Timeline、诊断快照及 Outbox 已存在，**When** 加入新关联能力，**Then** 原字段、摘要、身份与历史事实不被覆盖或重新解释为全事件唯一标识。

### 用户故事 2 - 观察实际诊断与模拟执行调用（优先级：P1）

开发者在本地采集短时 Trace，观察告警接收、聚合、诊断检索/生成/校验、人员决定、分发、票据消费、模拟应用和回执处理。主应用和独立 MCP 的连续调用保留真实父子关系，等待审批不会被算作持续执行耗时。

**优先级理由**：现有聊天 Trace 没有覆盖这些主链操作，仅日志无法呈现连续调用关系。

**独立测试**：诊断用本地语料；分发用完整隔离主应用和 MCP，采集实际 span，与业务事实和模拟应用次数核对。

**验收场景**：

1. **Given** 追踪开启且有有效诊断请求，**When** 实际检索、生成与校验完成，**Then** 能看到同次诊断的阶段、结果与诊断/Incident 身份，重复诊断不伪造第二次生成。
2. **Given** 人员拒绝 Action，**When** 观察追踪和模拟库事实，**Then** 有决定记录但没有模拟应用 span，副作用为 0。
3. **Given** 已批准 Action，**When** Worker 通过受保护 MCP 执行，**Then** 分发、服务端处理、票据消费、真实模拟应用和回执形成可核对的连续调用链；一个逻辑 Execution 最多应用一次。
4. **Given** MCP 调用进入超时工作线程，**When** 发生完成、超时或取消，**Then** 线程内仍能关联正确执行，后续复用线程不残留上一操作身份，追踪不把未知结果判为确定失败。

### 用户故事 3 - 故障恢复仍能核对且追踪不影响安全（优先级：P1）

响应人员遇到重启、双路径回执丢失或追踪出口不可用时，仍能依据稳定业务身份定位恢复过程和权威结论。追踪是辅助证据，不能授权执行或替代只追加审计。

**优先级理由**：恢复与安全隔离是现有平台价值，新增可观测能力不得削弱它们。

**独立测试**：沿用隔离 Worker 崩溃、回执双通道故障和 Relay 恢复测试，加入关联、秘密扫描及追踪不可用断言。

**验收场景**：

1. **Given** 未消费票据时 Worker 实际崩溃，**When** 重启恢复，**Then** 新阶段产生新 Trace，复用原 Action、Execution 和调度请求身份，只替票据，不声称旧进程最后 span 已成功结束。
2. **Given** 已消费且回执两通道丢失，**When** 截止后进入 UNKNOWN 并由可信迟到回执收敛，**Then** 可以凭稳定执行身份找到各阶段，禁止因缺少 Trace 重调写工具。
3. **Given** Trace 关闭、出口不可用或追踪上下文无效，**When** 同样业务请求执行，**Then** 结果、审批、幂等、回执事实和既有重试资格保持一致。
4. **Given** 未认证调用伪造业务身份与追踪字段，**When** 被拒绝，**Then** 不形成可信业务关联，不产生应用；日志和 Trace 不含本次实际凭据、票据或原始正文。

### 边界情况

- 非 anchor Alert 先处理并创建 Incident；anchor 尚未 PROCESSED 时诊断取到其他成员。历史 correlation 值不同不等于身份被篡改。
- 同一请求的接入过滤器、Controller 与错误处理均需共用一个尝试标识；不同 HTTP 回调尝试则各有新标识。
- 人员 sourceRequestId、人工结论正文 requestId、调度 requestId 有既定幂等/绑定含义，不能被 HTTP 尝试 ID 替换。
- 批量 Worker/Relay 操作按单条业务记录隔离，不继承调度线程前一次任务的上下文。
- 无效、超长、重复或全零传播 ID 降级为新短时 Trace，认证与输入校验仍按原顺序执行。
- 进程死亡可能丢失未导出的 span；没有历史采集的数据不能补造，恢复仅承诺业务身份可核对。

## 需求（必填）

### 功能需求

- **FR-001**：系统 MUST 明确区分 HTTP 请求尝试、业务来源意图、逻辑执行请求、Alert 关联和 Trace 身份；各层不得互相覆盖。
- **FR-002**：每次范围内 HTTP 请求 MUST 分配服务端尝试标识，响应成功/错误和安全日志共用该标识；不接受调用方指定服务端身份。
- **FR-003**：系统 MUST 保留每个 Alert 首次持久化的 correlationId、重复接收与重放语义；已知归属后以 incidentId 为聚合后操作的统一检索键。
- **FR-004**：系统 MUST 通过现有 Alert→Incident→Diagnosis/Action→Approval/Execution→Receipt/Event 关系串联证据；未知身份省略，不推测、不修改历史关联。
- **FR-005**：系统 MUST 为请求、单条 Worker 操作和连续出站调用产生有明确结束边界的短时 Trace；人工审批等待和跨重启不能维持同一个活跃 span。
- **FR-006**：诊断 Trace MUST 覆盖实际检索、生成与证据校验；幂等读取只记录重读，不能假装实际重新生成或调用模型。
- **FR-007**：受保护模拟调用与消费/回执回调 MUST 可关联连续调用的父子关系；追踪传播不进入授权、工具参数、绑定摘要或权威回执身份。
- **FR-008**：跨线程上下文 MUST 显式传递，并在完成、异常、取消及线程复用后清理/恢复；并发执行不得串线。
- **FR-009**：重试与崩溃恢复 MUST 保持原业务身份而区分当前尝试；缺失旧追踪上下文时允许新 Trace，不虚构历史父子关系。
- **FR-010**：安全日志和 span MUST 采用固定字段白名单及长度预算，禁止票据、服务凭据、签名、正文、诊断原文、任意模型内容或自由文本异常；未经验证的业务 ID 不作为可信字段。
- **FR-011**：追踪关闭、运行期导出失败或无效传播值 MUST NOT 改变业务处理、审批、票据、UNKNOWN 收敛、只追加审计、Outbox 身份及幂等/重试规则。
- **FR-012**：首版 MUST 提供可重复的本地采集验收，覆盖正常/拒绝/重复、多 Alert、跨线程、重启、回执丢失、Relay 重投与出口失败；实际身份扫描、运行命令、环境及结果须归档。
- **FR-013**：系统 MUST 保留上游聊天 Trace 的已验证行为和已有开关语义，新增能力不依赖启用付费模型或外部追踪服务。
- **FR-014**：首版 MUST NOT 增加业务表或迁移、重写历史数据、创建 Trace 页面、部署追踪平台、扩大真实工具范围或声明生产/性能验收。

### 关键实体（功能涉及数据时填写）

- **业务身份**：现有 Alert、Incident、Diagnosis、Action、Approval、Execution、Receipt 和 Event 身份；只认权威事实及既定关系。
- **请求尝试**：单次入站 HTTP 尝试，区别于稳定 sourceRequestId 和 dispatchRequestId。
- **短时 Trace**：某个正在运行的阶段及其连续调用；有独立 Trace/Span 身份、起止、可信业务字段和安全结果码。
- **安全证据**：现有持久化事实与本地采集结果的核对记录；日志或 Trace 不能成为审批或回执事实来源。

## 成功标准（必填）

### 可度量结果

- **SC-001**：指定成功/错误/重复/冲突场景中，100% 范围内响应尝试标识可与同次安全日志核对；重复业务身份全部保持。
- **SC-002**：两个告警聚合及非 anchor 先处理场景，100% 已完成的诊断、审批、执行、回执和事件操作可通过同一 Incident 身份检索，且两个 Alert 关联值保持不同。
- **SC-003**：正常批准链的实际阶段全部有可核对采集证据；连续跨进程调用无错误父子关系，拒绝链应用次数为 0，批准及恢复链各 Execution 应用次数为 1。
- **SC-004**：重启、回执丢失、并发、线程复用和追踪故障场景全部符合原安全状态及幂等规则，0 因追踪引起的新业务事实或写重试。
- **SC-005**：指定场景采集的日志、span 和安全快照对本次全部实际票据与服务凭据扫描命中 0，且无正文和非白名单内容。
